# 随从台词与通用音效（2026-09-22）

## 使用方式

语音页增加独立的 **通用音效** 勾选项，默认关闭，保存到
`workspace/settings.json` 的 `general_audio`。关闭并重新打开软件后保留选择。
原有 **配套音效 / 音乐** 继续独立控制卡牌同事件中的专属配音和登场曲。

- 随从登场：加入普通落地声；具有初始嘲讽、圣盾标签时加入相应展开声。
- 登场、攻击、死亡：加入该卡同事件真实引用的种族 / 材质 `Underlay` 垫音。
  例如奇利亚斯的机械攻击垫音。不会根据名字含“机械”“龙”等词随意拼声音。
- 两个选项同时开启时按资源 ID 去重。普通语音列表和 WAV 导出不混入这些通用声音。
- 选项改变会取消尚未完成的播放准备并停止本次伴随声音；新选择在下次播放生效。
  主音轨已经开始时可继续播放。
- 伴随声音仍支持暂停、恢复、音量和定位；主语音结束后保留尾声，每条伴随音轨
  的媒体时长上限仍为 15 秒。切换声音或停止时清理整组播放。

这是音频试听组合，不是游戏战斗模拟。默认普通落地声与音轨同步起播，不推断
游戏内当前身材、动态赋予关键词、金卡状态或特殊战斗触发时序。

## 台词缺失的原因与改动

英雄大量表情有客户端字符串键，但随从声音经常没有对应的本地字幕。
此次核对还发现以下独立问题：

1. **复刻卡定位到空页面**：核心系列使用新的 DBF ID，而语音常直接引用原卡资源。
   现在从语音文件名定位原卡，再验证原卡同一事件是否引用同一个预制体；只有
   验证一致才使用原卡 DBF ID。例如 `CORE_EX1_382 → EX1_382 / 1167`、
   `CORE_BOT_548 → BOT_548 / 49184`。不因名字相同或剥离前缀就借用台词。
2. **源码解析过窄**：现在读取 MediaWiki 展开后的 HTML，可处理页面模板转引；
   HTML 解析限定在“台词”标题内的登场、攻击、死亡条目。旧 wikitext 兼容解析
   修复了多行 quote 的结束标记被误判为台词区结束的问题。
3. **403 实际是浏览验证**：本次真实响应带有 `Cf-Mitigated: challenge`，正文是
   Cloudflare 验证页。不会再把访问失败当作“公开来源没有台词”，也不会让用户
   只能反复重开同一页面。

受阻时语音页显示 **在浏览窗口读取台词**。点击后，在独立窗口完成来源站要求的
验证，再点击 **读取本卡台词**。优先读取当前已显示的卡牌正文，并验证页面编号；
必要时请求同源 API。成功后自动回到当前语音页补充文本，并保存缓存。切换卡牌
期间完成读取，只保存缓存，不把结果写到另一张卡牌。

本地已有文字始终优先；公开文字逐条标注来源和“按唯一事件匹配”。随机多分支、
特殊条件、来源未收录和非简体中文片段不猜配。**这次改动不能保证所有随从都有
台词，也不能保证第三方站点的验证在每个网络环境都能通过。** 如验证持续失败，
本地音频仍可播放、导出；没有编造或用语音识别猜补台词。

## 实现与缓存

- `shared_audio.py` 集中保存可核对的试听规则。标签读取本地 `CARD_TAG`，只对
  随从启用。按需读取当前安装版本的 `Card_Play_Ally_SpellTable`，再沿其实际
  GUID 找音轨，无需先扫描全部资源；不会把嘲讽破盾、圣盾受击和升级音误作展开声。
- `transcripts.py` 不接触 Unity / SQLite，仍在独立网络线程运行。请求超时 8 秒、
  正文上限 1 MB；403 / 429 后暂停自动查询 60 秒，各卡缓存仍可立即读取。
- `transcript_browser.py` 使用独立 Qt Profile，远程页面没有 WebChannel，不能
  调用本地 API。仅允许台词站的顶层导航，不共享外部浏览器的 Cookie。自己的
  浏览会话保存在 `workspace/cache/transcript-browser`。
- 新字幕缓存位于 `workspace/cache/transcripts-v2`。非空缓存保留 30 天，明确的
  空结果保留 1 天。旧 `transcripts-v1` 成功结果继续可用，旧空结果重新查询，
  无需删除缓存或重建游戏索引。网络失败不写负缓存；过期成功结果可离线回退。
- GUI 读取与 HTTP 读取使用各自临时文件原子发布。缓存不可写时明确报错。
  原卡定位失败只影响公开来源补充，不移除已经解析出来的音频。
