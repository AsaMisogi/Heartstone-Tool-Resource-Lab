# 图鉴卡片与详情布局

本次调整使用现有 SQLite 图鉴索引、原生 JavaScript 和 CSS，无新增依赖，无需重建索引。

## 浏览变化

- 卡牌详情的基础信息和相关卡牌统一放在标签页内容的最底部。原画、完整卡面、语音、特效与源数据切换时位置保持一致，相关卡牌跳转和返回仍可使用。
- 基础信息不再展示打造／分解和赛制。列表赛制筛选、已有导出和底层元数据接口保持兼容。
- 图鉴卡片按名称、类型与稀有度、职业、种族、数值、系列和 ID 排列。职业与种族合并为一组，压缩行距、数值标签和内边距；保留多值换行及完整名称。
- 稀有度采用色线与文字双重标注；费用、攻击、生命分别以蓝、金、红色数值辅助阅读，同时保留明确文字。零费与零攻击正常显示，缺失数值不伪造为 0；武器显示耐久。
- 双职业、多种族、多系列全部展示，自然换行。没有种族时显示「无种族」，未知系列或职业保留编号。
- 英雄与皮肤展示职业；酒馆记录依据现有客户端图鉴分类显示「酒馆战棋 · 英雄 / 皮肤」，不按角色名称猜测职业，也不将通用英雄误归入某个职业。
- 卡牌名称与 ID 不再强制单行省略，支持字体缩放和长名称。发布日期排序的日期提示仍保留。

## 可调布局与列表视图（2026-09-22）

- 导航和页面名称统一为「英雄图鉴」，内容仍包含英雄与皮肤。
- 两个图鉴的筛选区域下方提供「卡片视图 / 列表视图」。列表使用横向缩略图和信息列，窄窗口会自动折行，整行可点击，键盘 Tab、Enter 和空格同样可用。
- 卡片原画采用方形画布、等比完整适配，不拉伸或裁切；悬停不再放大图片。不同原始纹理比例可能留边，这是完整展示原画的预期效果。
- 「卡片大小 · 紧凑到宽松」即时调整目标列宽（180–300 px）和内边距，默认 220 px，实际列宽随窗口自适应。百分比是相对默认列宽的比例，不影响全局字体设置。列表模式禁用此滑杆。
- 「恢复默认布局」恢复卡片视图及默认大小；重置搜索与筛选保留布局。卡牌和英雄图鉴分别记忆模式和大小，关闭重启仍保留。旧工作区自动使用默认布局。
- 详情原画标签页依次为品质切换、描述、趣闻、画师、原画；没有趣闻或画师时不保留空白块。基础信息仍在详情底部。

布局保存在现有 `view_state.<cards|heroes>.display`，后端校验模式与尺寸范围。滑杆 `input` 仅更新 CSS 变量，`change` 再写设置；切换视图只改变容器样式，不重建卡片、不重新查询、不重复解码，保留当前分页、筛选、顺序及连续加载内容。

## 实现与性能

`catalog_summaries` 仅批量读取当前页（最多 100 张）的过滤字段、详情字段、职业与系列。查询次数不随卡片数增长；职业与系列分开读取，避免多值联表的重复组合。不调用单卡详情、不解析 CardDef、不查询关联卡，也不新增网络访问。

前端沿用原有两项在途缩略图队列、图片缓存、分页、连续加载和屏幕外延迟绘制。新增摘要由原列表响应一次传回；卡片生成集中于 `catalogTile`，便于统一维护。所有动态文字经过 HTML 转义；颜色不作为唯一信息来源。
