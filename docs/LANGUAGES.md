# 语言设置与客户端切换

## 使用

- 默认开启“筛选器与资源语言同步”。更改筛选器后，新打开卡牌的语音使用该语言；在语音页更改资源语言，也会更新当前页面的筛选器。
- 在“资源与设置 → 语音语言”关闭同步后，筛选器继续按页面保存，资源语言跨卡牌、关闭详情和重启独立保存。返回衍生牌的上一级时也沿用最近选择。
- 资源语言旁的“显示其他已安装语言”默认关闭，勾选状态保存在工作区。主语言先显示，其他已安装语言逐种加载，按资源名和触发上下文对应到同一条语音，在主语言下方的分隔线后显示略小的台词、试听、重播与导出按钮。统一折叠／展开默认展开，本次运行中翻页、切卡沿用展开状态。
- 搜索、分类、场景分组和分页以主语言为基准，对照行跟随对应主行显示，不再出现第二套列表。无法确认对应音频时显示缺失提示，通用音效不重复展示。“导出全部语音”及卡牌整体导出使用主语言；其他语言可逐条导出。
- 额外语言显示客户端原始字幕。缺失字幕显示“暂无台词”；切为主语言后，可以使用原有公开台词补充及语音识别流程。
- 只统计磁盘上实际存在的语言音频包；有文本或语言清单不代表安装了该语言声音。语言包下载完成后重新连接目录，即可更新语言状态。

## 0.14 修复依据

本机英文 `Strings/enUS/PRESENCE.txt` 的 `TAG\tTEXT\tCOMMENT` 表头之前有六行 `#` 维护注释。
旧解析器只检查第一行，因此抛出“字幕来源不是 TAG/TEXT 格式的字符串表”。
`initialize` 此时已经创建资源读取器和部分数据库，前端却因初始化异常切到设置页，
没有接收就绪状态；其他页面的刷新直接返回，留下加载提示。
完整扫描完成事件后来携带后端状态，界面才恢复。这不表示必须全量扫描才能使用英语。

修复分三层：

1. TSV 解析器只跳过表头前的空行和注释，仍严格要求 TAG/TEXT。表头后的多行引号字段保持原样，避免将台词中的 `#` 内容误删。客户端和公开 TSV 来源共用规则。英文 AUDIOFILE 列也用于建立精确音频别名，冲突别名不采纳，准确 TAG 优先。
2. 客户端字符串按文件隔离读取失败。记录语言、文件名与错误，在设置中显示诊断；其他有效字幕、图鉴和音频继续可用。
3. 必需资源初始化失败时释放半成品连接，状态明确为未就绪。未连接页面显示操作提示，避免无限加载；重新连接可以重试。

## 调度与缓存

主语言保留原有分页、后台补词及仅当前页识别。额外语言同一时刻最多一个解析请求，
不提前解码 WAV、不自动识别或联网补词，只为主列表当前页创建对照行。各语言完成后预建音频匹配表，按资源名（保留分支编号）、事件、触发卡牌与原始条件匹配，不用列表序号或展示标题猜测；歧义匹配留空。折叠时不创建额外语言按钮，展开复用已解析数据。后台请求优先级低于前台；
遍历资源图时检查导航、播放和导出请求，必要时中断并在前台操作之后重试。
不可中断的单次原生读取仍需等待返回，但不会一次提交全部语言的解码任务。

页面代次用于丢弃旧结果，切卡、切语言、关闭或取消勾选后不再排队。
列表按钮携带实际资源语言，播放计划和导出均使用它，不复用主语言参数。
语音关系缓存升级至 v14，以更新旧解析流程留下的缺字幕查询；已有全量索引、收藏、
WAV 和用户导出保留。资源文件与字幕文件指纹继续参与语言缓存失效。

## 验证入口

`tests/test_languages14.py` 覆盖真实表头形态、多行字幕、坏文件隔离、重连恢复、偏好重启和初始化失败状态。
`tools/gui_languages14.py` 在独立工作区连接真实客户端，验证无完整索引启动、双向同步、独立记忆、
行内对应、统一折叠/展开与翻页、真实试听/导出和切卡取消；可用 WebView2 或 Qt 兼容引擎运行。
