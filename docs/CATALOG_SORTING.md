# 图鉴分类、排序与浏览体验

更新日期：2026-09-22。

## 使用变化

- 卡牌图鉴只查询卡牌；英雄与皮肤只查询英雄记录。关键词、组合筛选、收藏和翻页始终限定在当前分类内。可收集的英雄牌仍可在卡牌图鉴的“类别 → 英雄牌”中找到。
- 两页均可选择默认、名称、ID、发布日期排序，点击旁边的正序／倒序按钮切换方向。排序针对完整查询结果，在分页前完成；切换排序返回第一页，保留关键词和筛选。
- 两页分别记忆排序，重启后恢复。重置筛选不改变排序；排序偏好存于 Qt WebEngine 的 localStorage，不修改收藏和工作区设置。
- 默认正序保留原有核心系列优先的顺序；名称按当前显示语言排序，缺少翻译时回退英文，再回退索引名称。名称使用 SQLite NOCASE 文字顺序，英文忽略大小写，中文按字符顺序，**不是拼音排序**。ID 指卡片上显示的资源 ID，并按文本顺序排列，不是 DBF 数字编号。
- 中文输入法组词期间不查询，完成输入后等待 280 毫秒再查询。旧请求不能覆盖新输入；`%`、`_` 按普通文字搜索，查询不再命中画师和 JSON 字段名等非卡牌正文元数据。
- 日期排序会显示日期、来源提示及有日期参考的条目数。缺失日期在两个方向下均置于末尾，同日或同名条目用 ID 保持顺序稳定。
- 筛选栏改为等宽网格；小窗口缩短页头和统计区；卡牌长名称可换行，完整名称和 ID 可悬停查看。最近 256 张成功解析的缩略图 URL 按快照和语言缓存，排序及回看页面可复用。

## 日期口径与当前限制

本机 DBF 的 `CARD`、`CARD_HERO` 没有完整首发日期；`CARD_SET.m_releaseOrder` 只是顺序编号，`EventMap` 只是活动名称与 ID 的对应表，不能据此生成日期。

目前的“发布日期排序”使用随程序提供的离线日历，**尚不能提供所有卡牌和皮肤的精确首发时间**：

1. 一般卡牌采用已知所属系列中最早的上线日期，并标明“系列参考”。这不是迷你系列、提前赠送卡、冒险分区及每张衍生牌的独立首发日期。
2. 基础九职业英雄使用游戏正式上线日。其余独立皮肤／冒险角色没有可靠日期时显示“日期未知”；不能把整批皮肤都标成同一天，也不能用编号先后冒充发布日期。
3. 核心、传承、未知及尚未收录的系列不统一赋日期；地区首发差异不自动转换为中国时区日期。
4. 本次本地快照有 32,949 张卡牌、3,075 项英雄／皮肤。其中 15,173 张卡牌具有系列日期参考，9 个基础英雄有日期；**其余皮肤的日期资料仍待补齐**。界面实时显示当前筛选结果的覆盖数量。

日期事实核对来源（程序浏览时不联网）：

- [历史扩展系列日历](https://en.wikipedia.org/wiki/Hearthstone_expansions)：使用其日期事实，不复制文章正文；日期有地区差异或冲突时优先使用官方公告。
- [25.0 官方补丁说明](https://hearthstone.blizzard.com/en-gb/news/23882860)：巫妖王的进军与阿尔萨斯之路上线日期。
- [34.0 官方补丁说明](https://news.blizzard.com/en-us/article/24243857/34-0-patch-notes)：穿越时间流上线日期。
- [大地的裂变官方页面](https://hearthstone.blizzard.com/en-us/expansions-adventures/cataclysm)：2026 年对应扩展上线日期。

维护日历时修改 `pengpeng/releases.py`，核对本地系列枚举，并递增 `catalog.CATALOG_VERSION`。若将来补充独立皮肤日期，应使用明确的完整卡牌 ID 与可核对来源，不能以皮肤系列日期覆盖所有外观。

## 实现与兼容

串类的原因是 `list_cards(hero=False)` 原先没有添加 `hero=0`，实际查询了整个 cards 表；`hero=True` 才添加英雄条件。现改为两边都使用绑定参数限定 hero 标记，统计数字也采用相同边界。

保留原有的皮肤表、战棋皮肤表及游戏标签分类规则：可收集英雄牌仍属卡牌，非收集英雄及冒险敌人属英雄页面。本机验证仍能筛选出 46 张可收集英雄牌。

新增 `card_releases` 表与分类／默认排序索引，不改变 cards 表的列，不清空原画定义、收藏、音频索引和导出。图鉴版本升级时自动读取 DBF 重建筛选与日期关系，无需重新执行全量资源扫描。更新过程中沿用 SQLite 事务；成功后才更新图鉴版本标记。

排序字段和方向均由后端白名单决定，外部输入不直接拼接 SQL 排序语句；分页始终应用于排好序的结果。默认排序索引与查询表达式一致，避免排序时读取全部卡牌文本。名称排序从本地 JSON 提取显示名称，仍在解析进程执行，不占用 GUI 线程。
